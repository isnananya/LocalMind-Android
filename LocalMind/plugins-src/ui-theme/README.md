# 暖橙主题 · LocalMind 界面插件

这个插件能改**整个应用的外观** —— 主色、圆角、字号、标签栏。

## 装法

**我的 → 插件 → 右上角 +**，选这个 zip。装完立刻生效。

## 里面改了什么

| 令牌 | 值 | 效果 |
| --- | --- | --- |
| `accent` | `#FF6B35` | 主色换成暖橙（按钮、选中态、链接） |
| `cardCorner` | `18` | 卡片圆角放大 |
| `controlCorner` | `12` | 控件圆角放大 |
| `groupedBackground` | `#FDF9F6` | 页面底色带一点暖调 |
| `darkTokens.accent` | `#FF8A5C` | 深色模式下用更亮的橙（否则橙色在纯黑上会发暗） |

## 全部可改的令牌

装完之后，在「我的 → 插件」里点这个插件的「写出示例」，
会在应用目录生成一份 `可改的令牌.txt`，列出了所有令牌、取值范围和默认值。

主要几类：

| 类别 | 令牌 |
| --- | --- |
| 颜色 | `accent` `accentDark` `danger` `success` |
| 背景 | `groupedBackground` `cardBackground`（各有一个 `…Dark` 深色版） |
| 圆角 | `cardCorner` `controlCorner` `sheetCorner`（单位 dp，0–32） |
| 排版 | `bodySize` `fontScale`（0.8–1.4） |
| 导航 | `tabStyle`（`glass` / `plain` / `hidden`）、`showTabBarLabels`、`navTitleAlign` |

另外还有三个不是令牌的顶层字段：

```json
{
  "tabs": ["chat", "models", "me"],   // 标签栏显示哪几个、什么顺序
  "startTab": "chat",                  // 打开应用先进哪一页
  "appName": "我的助手"                // 覆盖应用标题
}
```

## 为什么是"令牌"而不是代码

插件**不能**往应用里塞 Compose 代码 —— 那等于把 `DexClassLoader` 请回来，
"装个插件"会立刻变成"装个后门"。

所以界面插件只能从上面这份**固定名单**里挑值。换来三件事：

1. **安全**：令牌是数据，不可能执行任何东西。最坏情况是配色难看。
2. **不崩**：任何越界值都会被夹到合法区间。你写 `cardCorner: 999`，
   它会被夹到 32；写 `accent: "红色"`，会回退到默认蓝。**插件写错不会让应用挂掉。**
3. **可叠加**：浅色 / 深色分开给，用户的手动覆盖还能再盖一层。

代价是表达力有上限。但"换主色、改圆角、藏掉某个标签页"覆盖了绝大多数人
想要的"改 UI"。真需要任意布局的人应该去改源码，而不是装插件。

## 优先级

```
内置 iOS 原色  →  界面插件  →  用户手动覆盖
```

用户永远有最终话语权：插件不该能钉死一个你改不掉的颜色。

## 多个界面插件会怎样

同时启用多个时，**最后启用的那个生效**（不是叠加）。两个主题的颜色混在一起
通常都很难看，而且出了问题没法判断是谁干的。所以只取一个，并在插件页
如实显示当前用的是哪个。

## 改完怎么装回来

1. 用任意文本编辑器改 `ui.json`
2. 把**文件**（不是文件夹）重新压成 zip
3. 导入
